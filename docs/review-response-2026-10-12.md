## 本批各项怎么修的

### F01 — 解绑只释放被移除的那个关联

根因是我自己引入的：为了修「解绑后没什么可释放」，我把 `planSleep` 移到了删除之前——它算的是**整个工程休眠**的计划，于是从「释放不到」变成「释放全部」。

新增纯函数 `planUnbind(state, workspaceId, bindingId)`（`src/coordinator.js`）：只把被移除关联对应的包当作候选，并在模拟删除后的状态上重新计算使用关系；被禁用的关联（`enabled:false`）直接返回空计划，因为它本来就没占用任何东西。

**我未采纳评审建议的一部分**，并说明理由：评审还建议「让原生释放遵守空闲保护，避免解绑路径绕过休眠的忙碌检查」。我没有加。休眠排队是因为它是关于一个**正在使用中**的工程的背景意图；而解绑是用户刚刚做出的**显式重配置**——刚刚说了这个工程不再需要这个脚手架，而且工具列表按模型请求固定，进行中的回合不会被切断。这是判断分歧，不是遗漏；如果认为应该排队，可以再改。

### F02 — 操作级串行

新增 `#critical()`：`src/operations.js` 里一条 promise 链，把**完整变更操作**（版本校验 → 原生副作用 → 提交 → 事件对账）包成互斥段。延迟休眠与事件对账也走同一条链。

`#critical` 不可重入（嵌套会等待只有自己才能推进的链，从而挂死），这一点在代码注释里写明了；每个入口只在最外层取一次。

**背景模式顺带补了两个隐患**：进度条目原先依赖 `#dispatch` 同步登记，串行后不再保证，改为在入队前登记；队列内的失败原先会被静默吞掉（正是 F08 那类「失败报成成功」），现在写入进度条目，调用方轮询可见。

### F03 / F04 — 真实路径边界

由 subagent 实现，我逐行审查：

- **F04**：`walk()` 改用 `lstat()`（`stat()` 会先跟随链接，所以原来的 `isSymbolicLink()` 永远为假），并对 `readdir` 的 dirent 直接判 `isSymbolicLink()`。实测确认 Windows junction 在 `lstat` 下 `isSymbolicLink()` 为真。
- **F03**：新增 `resolveInsideReal()`——先做原有的字面检查，再 `realpath` 工程根，并解析目标**最近的已存在祖先**的真实路径，要求落在真实根内。`resolveInside` 本身**一字未改**，`operations.js` 的 tar 解包路径不受影响。`inspectTarball` 本来就拒绝 link 类型的 tar 条目，所以解包侧没有同类缺口。

**残余风险如实保留**：检查与写入是两次系统调用，能替换目录的人在两者之间插入 junction 仍可改写目标；Node 没有 `openat` 这类把检查与写入绑定的 API，无法在这一层关闭。代码注释与本文都写明了，没有假装关掉。

### F12 — 自动恢复必须登记使用关系

`index.js` 里删掉了「所有包都已启用就提前返回」的判断。原先它把「原生没什么要启用的」等同于「没什么要恢复的」，于是工程停在 `sleeping`、从不登记为持有者，随后另一个工程休眠就把共享包停掉了。

现在即使所有包都已启用也照常提交 awake 意图（`wake` 会返回 `already-enabled`），并顺带取消该工程排队的休眠。自动路径仍然不跑包管理器。

## 顺带改正的一处**文档承诺**（F10 的一部分）

README 原先写着「有任何 `conflict` 时整批阻止，不会写入部分文件」。这与实现不符：预览阶段确实整批检查，但**预览之后**才出现的冲突是在应用阶段逐个发现的，所以后项冲突时前项文件已经落盘。评审说得对。

这个**代码**问题属于第二批（F10，未修），但**那句话是假的**，与本次修复无关地必须改掉——否则声明又一次跑在证据前面。README 已改为如实描述：预览整批阻止；应用阶段若发现预览后被改动的目标，会中止后续写入并报告已创建的文件。
